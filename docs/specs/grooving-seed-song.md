# Grooving: 曲から始める (種の曲)

用語は [GLOSSARY.md](../../GLOSSARY.md) に従う (Grooving・気分・種の曲・方向・聴き慣れた曲・新しい曲・組・曲の聞き取り・音の元)。Grooving の仕組みは [Grooving](grooving.md)、曲の聞き取りは [曲の聞き取り](song-recognition.md) の上に足し、この仕様に書いていないことはそれぞれの仕様のとおりにする。

## Problem Statement

「この曲みたいな曲をもっと聴きたい」と思っても、Grooving の気分は YTM の項目か言葉でしか選べない。今流れている曲や、街やほかのアプリで耳にして曲の聞き取りで見つけた曲を起点にしたくても、その曲の雰囲気を言葉にし直す必要がある。曲の聞き取りは、見つけた曲を検索するところで終わり、そこから先に広げる手がない。

## Solution

Grooving の気分を選ぶ画面に、3 つ目の選び方 **「曲から」** を足す。そこで **種の曲** として、次のどちらかを選ぶ。

- **今再生中の曲**
- **直近に聞き取った曲** (曲の聞き取りで見つけた 1 曲)。画面の中の聞き取るボタンで、その場で聞き取ることもできる。

種の曲を選ぶと、YTM でその曲を探し、その曲の関連曲 (YTM のラジオの並び) を中心に候補を集める。方向 (寄せる・外す・ミックス) と組の数は今までどおり選べ、LLM には「〈曲名〉 / 〈アーティスト〉 のような曲」を気分として渡す。種の曲そのものは、組にもリストにも入れない。

Shazam が無効か API Key が無いときは、「今再生中の曲」だけを出す。検索欄の横のアイコンの動き (見つかったら検索する) は変えない。

## User Stories

### 選び方
1. 利用者として、気分を選ぶ画面で、「項目を選ぶ」「言葉で書く」に並んで「曲から」を選びたい。それは、言葉にしにくい雰囲気を、曲で伝えたいからだ。
2. 利用者として、「曲から」で、今再生中の曲を種の曲に選びたい。それは、今聴いている曲が気に入ったとき、その流れのまま広げたいからだ。
3. 利用者として、今再生中の曲の候補には、ジャケット・曲名・アーティストが出てほしい。それは、どの曲を種にするのか確かめたいからだ。
4. 利用者として、何も再生していないとき (または広告のとき) は、今再生中の曲を選べず、その理由が分かってほしい。それは、なぜ選べないのか迷いたくないからだ。
5. 利用者として、「曲から」で、直近に聞き取った曲を種の曲に選びたい。それは、ほかで耳にして気になった曲の雰囲気で聴きたいからだ。
6. 利用者として、「曲から」の画面に聞き取るボタンがほしい。押すと、検索欄の横のアイコンと同じく音の元を 5 秒録り、見つかった曲がその場で直近に聞き取った曲になってほしい。それは、検索欄のアイコンに持ち替えずに続けたいからだ。
7. 利用者として、「曲から」の画面の聞き取るボタンで見つかったときは、YTM の検索結果を開かないでほしい。それは、Grooving の画面のまま進めたいからだ。
8. 利用者として、聞き取っている間はボタンが点滅し、問い合わせている間は回転してほしい。見つからないときやエラーのときは、ボタンの下に検索欄のアイコンと同じ文が出てほしい。それは、聞き取りの様子が今と同じように分かってほしいからだ。
9. 利用者として、検索欄の横のアイコンで聞き取って見つかった曲も、直近に聞き取った曲として「曲から」に出てほしい。それは、先に聞き取っておいて、あとから Grooving で使いたいからだ。
10. 利用者として、Shazam が無効か API Key が無いときは、「曲から」には今再生中の曲だけが出てほしい。それは、使えない聞き取りのボタンを押したくないからだ。
11. 利用者として、直近に聞き取った曲は、アプリを閉じたら忘れてほしい。それは、聞き取りの記録がアプリに残り続けるのは気持ちが悪いからだ。
12. 利用者として、「曲から」で選んだ種の曲は、ほかのページに移って戻っても選んだままであってほしい。それは、今の気分の選びかけと同じく、選び直したくないからだ。
13. 利用者として、「曲から」は、ムードやジャンルとの掛け合わせや、言葉との組み合わせにならないでほしい (どれか 1 つの選び方)。それは、選ぶことが多いと始めるまでが面倒だからだ。

### 候補
14. 利用者として、種の曲を選んで始めたら、その曲の関連曲 (YTM のラジオの並び) を中心に候補を集めてほしい。それは、その曲に近い曲を聴きたいからだ。
15. 利用者として、「寄せる」では、関連曲のうち聴き慣れた曲と、履歴・高評価のうち種の曲のアーティストの曲から選ばれてほしい。それは、知っている曲の中で、その曲に近いものを聴きたいからだ。
16. 利用者として、「外す」では、関連曲のうち新しい曲から選ばれてほしい。それは、その曲に近い知らない曲を見つけたいからだ。
17. 利用者として、「ミックス」では、その両方から選ばれてほしい。それは、今までの Grooving と同じ方向の意味であってほしいからだ。
18. 利用者として、候補が足りないときは、種の曲のアーティスト名で検索した曲で補い、補ったことを知らせてほしい。それは、関連曲が少ない曲でも使いたいからだ。
19. 利用者として、種の曲そのものは、組にもリストにも入らないでほしい。それは、もう知っている曲を選ばされても意味が無いからだ。
20. 利用者として、種の曲が YouTube Music で見つからないときは、「その曲が YouTube Music で見つからない」と知らせ、やり直せてほしい。それは、聞き取った曲が YTM に無いこともあるからだ。

### LLM と同意
21. 利用者として、LLM には、気分として「〈曲名〉 / 〈アーティスト〉 のような曲」が渡ってほしい。それは、組とリストがその曲の雰囲気に沿ってほしいからだ。
22. 利用者として、履歴を送らない設定でも、種の曲の曲名とアーティストは LLM に送ってよい。それは、自分で選んだ気分の一部だからだ。
23. 利用者として、初めて使うときの同意の画面の「送るもの」に、「選んだ曲 (曲から選んだとき)」が書かれていてほしい。それは、何が送られるかを知ってから同意したいからだ。
24. 利用者として、組・できあがりの画面とプレイリストの名前の元に出る気分の名前は、「〈曲名〉 / 〈アーティスト〉 から」のようになってほしい。それは、どの曲から作ったリストか分かりたいからだ。

## Implementation Decisions

### 曲の聞き取り (共有モジュール・メインプロセス)
- **応答の解釈**: 見つかったときの結果に、検索の文字列に加えて、曲名とアーティストを別々に持たせる (`track.title`・`track.subtitle`)。検索の文字列の作り方は変えない。
- **聞き取りの状態の決定**: 「アイコンが押された」の出来事に、**行き先** (検索 / Grooving) を持たせる。見つかったときのすることは、行き先が検索なら今までどおり「検索する」、Grooving なら「直近に聞き取った曲として覚える」(検索しない)。どちらの行き先でも、見つかった曲は直近に聞き取った曲として覚える (検索の行き先では、検索に加えて覚える)。録音中の取り消し・問い合わせ中に押しても何も起きない、などの今の決まりは行き先によらない。
- **直近に聞き取った曲**: メインの MemoryStore に `{ title, artist }` か null で置く (設定のファイルには書かない。アプリを閉じたら忘れる)。Grooving のサービスはここから読む。
- **押す合図**: YTM 画面から、行き先 Grooving の「押された」を送る新しい合図を足す (preload の op と IPC の名前を、今の押す合図の隣に足す)。聞き取りの状態 (待機・録音中・検索中・知らせの文) は、今と同じ状態の知らせで YTM 画面に送り、Grooving の画面のボタンもそれを見て描く。

### Grooving (共有モジュール)
- **気分の型**: 「曲から」の気分 `{ kind: "song", song: { title, artist, videoId | null, thumbnail | null } }` を足す。videoId は今再生中の曲なら入り、聞き取った曲なら null (ページが検索で探す)。
- **気分の名前**: 「〈曲名〉 / 〈アーティスト〉 から」(英語は "From 〈title〉 / 〈artist〉")。
- **候補の組み立て**: 種の曲の videoId と、種の曲と同じ曲名・アーティストの曲 (1 人目のアーティストを小文字で比べる) を候補から除く。寄せるの候補には、履歴・高評価のうち種の曲のアーティストの曲を含める (今の寄せるの集め方で入る)。
- **候補の失敗の理由** に「種の曲が YouTube Music で見つからない」を足す。
- **画面に出すもの (view state)**: 気分を選ぶ画面のために、今再生中の曲 (曲名・アーティスト・ジャケット・videoId、無ければ null)・直近に聞き取った曲 (無ければ null)・その場で聞き取れるか (Shazam が有効で Key がある) を含める。

### Grooving の受け持ち (メインプロセス)
- 今再生中の曲は PlayerStateStore から、直近に聞き取った曲は MemoryStore から読み、変わったら view state を送り直す (気分を選ぶ画面を出しているあいだ)。
- 候補を集める: 気分が「曲から」のとき、ページの候補集めに種の曲を渡す。ページは次の順に集めて返す。
  1. videoId が無ければ、`〈曲名〉 〈アーティスト〉` で曲を検索し、1 件目の曲を種の曲とする。見つからなければ「見つからない」を返す。
  2. 種の曲の関連曲 (今の関連曲の取り方。`next` と `browse` の 2 回) を気分の曲 (`mood`) にする。
  3. 履歴・高評価 (寄せるとミックス、履歴を送るとき) は今までどおり。
  4. 関連曲の候補が 30 曲に満たないときは、アーティスト名で曲を検索して補い、補ったことを返す。
  要求の数は、検索 1・関連曲 2・履歴 1・高評価 1・補いの検索 1 で、最大 6 回 (今の上限に収まる)。
- LLM: 検索語の頼みはしない。組とリストの頼みでは、気分として「〈曲名〉 / 〈アーティスト〉 のような曲」(表示の言語に合わせる) を渡す。
- 履歴を送らない設定でも、種の曲の曲名とアーティストを送る。

### YTM 画面
- 気分を選ぶ画面の選び方のタブに「曲から」/ "From a song" を足す。中身は、今再生中の曲のカード、直近に聞き取った曲のカード、聞き取るボタン (その場で聞き取れるときだけ)。カードは 1 つだけ選べる。選んでいない・選べる曲が無いときは「始める」を押せない。
- 選びかけ (選んだカード) は、今の選びかけと同じくページが覚え、ページを読み込み直したら捨てる。
- 同意の画面の「送るもの」の文に「選んだ曲 (曲から選んだとき)」を足す。
- 文言は表示の言語 (英語・日本語) に従い、Grooving の文言の置き場に足す。

## Testing Decisions

- よいテストは、共有モジュールの関数に入力を与え、出力だけを確かめる。テストは Vitest で、`src/shared/song-recognition/` と `src/shared/grooving/` の今のテストと同じ書き方にする。
- **合意済みの seam** (この 3 つでテストを先に書く):
  1. **曲の聞き取りの状態の決定**: 行き先が検索のとき今までどおり検索すること、行き先が Grooving のとき検索せずに覚えること、どちらでも覚えること、録音中の取り消しと問い合わせ中の押下が行き先によらないこと。
  2. **応答の解釈**: 見つかったときに曲名とアーティストが別々に取れること、検索の文字列が変わらないこと。
  3. **候補の組み立て**: 種の曲 (videoId 一致、曲名とアーティスト一致) が候補から除かれること、方向ごとの絞り込みが今までどおりであること。
  加えて、**Grooving の進行の決定** の今のテストに、気分が「曲から」で始められること、種の曲が見つからない失敗とやり直しを足す。
- 実際の聞き取り、ページでの種の曲の検索と関連曲の取得、画面の見た目は、開発版で確かめる。

## Out of Scope

- 種の曲を 2 曲以上にすること。
- 種の曲を、キューや履歴や検索結果から選ぶこと (今再生中の曲と直近に聞き取った曲だけ)。
- 聞き取った曲の履歴を残すこと。
- 種の曲とムード・ジャンルの掛け合わせ。
- 検索欄の横のアイコンの動きを変えること (見つかったら検索する、は今のまま)。

## Further Notes

- 種の曲の曲名とアーティストは、利用者が自分で選んだ気分の一部として、履歴を送らない設定でも LLM に送る。2026-11-06 に利用者が決めた (design-flow の Q23)。

## 状態の図

pstack の `/statechart` の検査は、利用者の許可を取っていないため行っていない (TLC と Java のダウンロードが要る)。図と利用者の合意で Ready とする。Grooving の進行の図 (grooving.md) は変えず、気分を選ぶ画面の中の「曲から」の選びかけと、曲の聞き取りの行き先を描く。

```mermaid
stateDiagram-v2
    state "曲からの選びかけ" as Pick {
        [*] --> 選んでいない
        選んでいない --> 再生中の曲を選んでいる: 再生中の曲のカードを押す (再生中の曲がある)
        選んでいない --> 聞き取った曲を選んでいる: 聞き取った曲のカードを押す
        再生中の曲を選んでいる --> 聞き取った曲を選んでいる: 聞き取った曲のカードを押す
        聞き取った曲を選んでいる --> 再生中の曲を選んでいる: 再生中の曲のカードを押す
        聞き取った曲を選んでいる --> 聞き取った曲を選んでいる: その場で聞き取って見つかる (新しい曲に入れ替わる)
        選んでいない --> 聞き取った曲を選んでいる: その場で聞き取って見つかる
        再生中の曲を選んでいる --> 再生中の曲を選んでいる: 再生中の曲が変わる (選んだ曲のまま)
    }
    --
    state "聞き取り" as Recog {
        [*] --> 待機
        待機 --> 録音中: 押す (行き先: 検索 / Grooving)
        録音中 --> 待機: もう一度押す (取り消し)
        録音中 --> 問い合わせ中: 5 秒録れた
        問い合わせ中 --> 検索して覚えた: 見つかる (行き先: 検索)
        問い合わせ中 --> 覚えた: 見つかる (行き先: Grooving)
        問い合わせ中 --> 知らせの文: 見つからない・エラー
        検索して覚えた --> 待機
        覚えた --> 待機
        知らせの文 --> 待機: 4 秒たつ
    }

    %% never 行き先が Grooving の聞き取りで、YTM の検索結果が開く
    %% never 選べる曲が無いのに「始める」を押せる
    %% never 種の曲が、組かリストに入る
    %% never 直近に聞き取った曲が、アプリを閉じたあとも残る
    %% never Shazam が使えないのに、聞き取るボタンが出る
```
