# 背景動画の元に「再生中の動画」を足し、Glass テーマを足す

用語は [GLOSSARY.md](../../GLOSSARY.md) に従う。前提の仕様は [theme-bgvideo-discord.md](theme-bgvideo-discord.md)。再生中の動画の写し方は [ADR 0002](../adr/0002-playing-video-canvas-in-ytm-view.md) に、ローカルの動画ファイルの流し方は [ADR 0001](../adr/0001-background-video-below-ytm-view.md) に従う。

## Problem Statement

背景動画は、利用者が選んだ 1 本のローカルの動画ファイルしか流せない。聴いている曲の MV を背景に大きく流したくても、動画ファイルを用意する必要があり、曲が変わっても背景は変わらない。

また、背景動画を出している間は、YTM 画面のナビバー・サイドバー・プレイヤーバーが完全に透明になる。読みやすさはマスクの濃さで調整するしかない。面だけを半透明のすりガラスにして、後ろの動画を透かしながら読みやすくする見た目 (Glass UI) は選べない。

## Solution

**背景動画の元**: 背景動画の設定に「元」を足し、**再生中の動画** と **ローカルの動画ファイル** から選べるようにする。既定は再生中の動画。
- 再生中の動画を選ぶと、YouTube Music のプレイヤーが今流している映像 (MV、または曲のジャケットの静止画) が、メインウィンドウの背景全体に大きく流れる。
- 曲が変われば背景も変わり、音とずれない。
- マスクの濃さ・ぼかし、見えない間と全画面の間に止める扱いは、ローカルの動画ファイルと同じ。

**Glass テーマ**: 同梱テーマに **Glass** を足す。YTM 画面のナビバー・サイドバー・プレイヤーバー・メニューが、半透明の面 + すりガラスのぼかし + 細い明るい縁になり、背景動画がその後ろに透けて見える。
- テーマには色ではない項目「面のぼかし」を足す。テーマファイルからも使える。

## User Stories

### 背景動画の元

1. 利用者として、背景動画の元に「再生中の動画」を選びたい。それは、聴いている曲の MV を背景に大きく流したいからだ。
2. 利用者として、曲が変わったら、背景の映像も次の曲のものに変わってほしい。それは、手で選び直したくないからだ。
3. 利用者として、背景の映像と音がずれないでほしい。それは、MV の口の動きや振り付けがずれると気になるからだ。
4. 利用者として、プレイヤーの画面を開いて中央に MV が出ている間も、背景に同じ映像がぼかされて広がってほしい。それは、画面全体を 1 つの雰囲気にしたいからだ。
5. 利用者として、プレイヤーの画面を閉じて下のバーだけにしている間も、背景に映像が流れてほしい。それは、曲を探しながらでも MV を感じていたいからだ。
6. 利用者として、曲を一時停止したら、背景は最後の場面で止まってほしい。それは、急に背景が消えると落ち着かないからだ。
7. 利用者として、MV の無い曲 (「曲」モード・音声だけの曲) では、プレイヤーが出しているジャケットの静止画が背景に出てほしい。それは、背景が空になるより自然だからだ。
8. 利用者として、アプリを起動した直後で、まだ曲を読み込んでいない間は、テーマの背景色で表示されてほしい。それは、何も無い黒い映像が出ても意味がないからだ。
9. 利用者として、YouTube Music がサインインの画面などを出している間は、背景動画が出ないでほしい。それは、サインインの画面は読みやすくあってほしいからだ。
10. 利用者として、ローカルの動画ファイルも、これまでどおり選べてほしい。それは、気に入っている映像を流したいときもあるからだ。
11. 利用者として、設定画面の「Source」で、Playing video と Video file を切り替えたい。それは、元がどちらかが一目で分かるからだ。
12. 利用者として、ファイルを選ぶ欄と「ファイルが見つかりません」の知らせは、Video file を選んだときだけ出てほしい。それは、関係ない欄が出ていると迷うからだ。
13. 利用者として、マスクの濃さとぼかしは、元を切り替えても同じ値のままであってほしい。それは、元ごとに調整し直したくないからだ。
14. 利用者として、ウィンドウを最小化したりトレイに隠したりしている間と、全画面の間は、背景の描き写しが止まってほしい。それは、見えない映像に CPU や GPU を使ってほしくないからだ。
15. 利用者として、OS で「アニメーションを減らす」にしているときは、背景が動き続けないでほしい。曲が変わったときと一時停止したときに、1 枚だけ描き直されればよい。それは、動きで気分が悪くなることがあるからだ。
16. 利用者として、広告が流れている間は、その映像がそのまま背景に出てもよい。それは、広告を見分ける仕組みで不具合が出るより分かりやすいからだ。

### Glass テーマ

17. 利用者として、同梱テーマから Glass を選びたい。それは、背景動画を透かしながら読みやすい見た目にしたいからだ。
18. 利用者として、Glass のとき、ナビバー・サイドバー・プレイヤーバー・メニューが、すりガラスのように後ろをぼかした半透明の面になってほしい。それは、動画の雰囲気を残しつつ文字を読みやすくしたいからだ。
19. 利用者として、Glass の面には、細い明るい縁があってほしい。それは、面の境目が分かるようにしたいからだ。
20. 利用者として、テーマファイルに `--ytmd-surface-blur: 20px;` と書けば、自作のテーマでもすりガラスにしたい。それは、Glass の色だけを変えたいことがあるからだ。
21. 利用者として、今の Default・Midnight・Forest と、面のぼかしを書いていないテーマファイルは、これまでと同じ見た目のままであってほしい。それは、勝手に見た目が変わると困るからだ。
22. 利用者として、面のぼかしの値が読めないときは、ぼかさずに使えて、設定画面でそれを知りたい。それは、書き間違いで見た目が崩れると困るからだ。
23. 利用者として、背景動画がオフのときも Glass を選べてほしい。それは、暗い背景に淡い面が並ぶ見た目も気に入るかもしれないからだ。
24. 利用者として、Glass でも、設定やミニプレイヤーなどのアプリ画面は、半透明の色で描かれれば十分だ。それは、その後ろには動画が無いからだ。

## Implementation Decisions

### 背景動画の元
- **設定 (appearance)**: `backgroundVideoSource` を足す。値は定数オブジェクト `BackgroundVideoSource` (Playing: "playing" / File: "file") で、既定は Playing。既存の利用者にも、版の移行で既定値を入れる。今の `backgroundVideoPath` などはそのまま使う。
- **背景動画の状態の決定 (共有モジュール、既存の関数を広げる)**:
  - 入力に `source`、`videoAvailable` (再生中の動画の映像があるか)、`reducedMotion` を足す。
  - 「表示できる映像がある」は、元が Playing なら `videoAvailable`、File なら `fileFound` で決める。
  - 出力に `motion` (定数オブジェクト: Continuous / Still) を足す。`reducedMotion` のときは Still、それ以外は Continuous。
  - Still のときは、曲が変わったときと一時停止したときにだけ 1 枚描く (ローカルの動画ファイルは、止めた 1 枚を出す)。
  - 今の `video` (NotShown / Playing / Paused / Hidden) と `ytmBackground` の意味は変えない。
- **再生中の動画の描き写し (YTM 画面の中、新規)**:
  - YTM のページのスクリプト (main world) に、描き写し役を置く。`html` の直下に、画面全体を覆う `position: fixed`・一番奥の canvas と、その上のマスクの層を置く。
  - プレイヤーの `<video>` の `requestVideoFrameCallback` でフレームが届くたびに、canvas に「覆うように」(object-fit: cover 相当) 描く。
  - ぼかしは canvas に CSS の `filter: blur()` をかけ、マスクの色はテーマの背景色にする。
  - 状態 (表示するか・Continuous / Still・マスクの濃さ・ぼかし・マスクの色) は、BackgroundVideoManager が YTM のビューに IPC で送り、preload から main world に渡す。
  - `<video>` の要素が作り直されたら、付け直す。
- **映像があるか**: YTM のページで、`<video>` に `videoWidth > 0` の映像が読み込まれているか、そして今のページが music.youtube.com かを見て、BackgroundVideoManager に知らせる。
- **YTM の画面の透明化**:
  - 元が Playing のときは、canvas が YTM のページの中にあるので、YTM のビュー自体は透明にしない (背景色のまま)。ページの中の要素 (`body`・`ytmusic-app` など) の背景だけを透明にする。
  - 元が File のときは、今と同じ (ビューを透明にし、下の背景動画のビューで流す)。
  - 背景動画のビューは、元が Playing の間は何も出さない。
- **設定画面**: Appearance タブの背景動画の項目に「Source」の選択 (Playing video / Video file) を足す。ファイルの欄と「Video file not found」の知らせは、Video file のときだけ出す。

### Glass テーマ
- **テーマの読み込み (共有モジュール、既存の関数を広げる)**:
  - 色ではない項目 `surfaceBlur` (px の数値) を足す。テーマファイルでは `--ytmd-surface-blur: <長さ>;` (px か 0) で書く。
  - 書いていないときは 0。読めない値 (例えば `abc`、負の値、`px` 以外の単位) のときは 0 にして、読めなかった項目の一覧に入れる。上限は 40px に丸める。
- **同梱テーマ**: `BundledTheme` に Glass を足す。値は、背景 `#0A0A12`・面 `rgba(255,255,255,0.08)`・文字 `#FFFFFF`・控えめな文字 `rgba(255,255,255,0.65)`・アクセント `#8AB4FF`・枠線 `rgba(255,255,255,0.18)`・面のぼかし 20px。`ThemeSelection` は `BundledTheme` から作られているので、自動で選択肢に入る。
- **YTM 画面への注入 (ThemeManager)**:
  - `surfaceBlur > 0` のテーマでは、ナビバー・サイドバー・プレイヤーバー・メニューとダイアログの面に、面の色・`backdrop-filter: blur(<surfaceBlur>px)`・枠線の色の 1px の縁を当てる。
  - 背景動画を出している間の透明化 (BackgroundVideoManager) は、`surfaceBlur > 0` のときは、これらの面を透明にしない。ページの背景だけを透明にする。
  - `surfaceBlur = 0` のときは、今と同じ。
- **アプリ画面**: ぼかしは当てず、今と同じく色だけを当てる。タイトルバーの重ね表示は、背景色を不透明にして塗る (半透明の色は使えないため。`toNativeColor` はアルファを落とさないので、背景の色をそのまま使う。Glass の背景は不透明)。
- **設定画面**: テーマの選択肢に Glass が出る。面のぼかしが読めなかったときは、今の「Could not read: …」に `Surface blur` として出す。

## Testing Decisions

- 合意済みの seam (今ある 2 つを広げる。新しい境界は作らない):
  1. **テーマの読み込み**: 同梱の Glass の値、`--ytmd-surface-blur` の読み込み (書いていない → 0、`20px` → 20、`0` → 0、読めない値 → 0 で一覧に入る、上限で丸める)、今の 3 つの同梱テーマの `surfaceBlur` が 0 であること。
  2. **背景動画の状態の決定**: 元 (Playing / File)・`videoAvailable`・`fileFound`・`enabled`・`window`・`reducedMotion` の全組み合わせ (96 通り) で、下の状態の図の `%% never` の規則が破れないこと。今のテストの期待は、`source: File`・`reducedMotion: false` の場合として、そのまま通ること。
- テストしないもの (アプリを起動して確かめる):
  - canvas への描き写し、映像と音のずれ、プレイヤーの画面の開け閉めと「曲」モード
  - すりガラスの見た目、Default などの見た目が変わらないこと

## Out of Scope

- 広告の映像を見分けて隠すこと。
- 背景用に高い画質を求めること (YTM が選ぶ画質のまま拡大する)。
- アプリ画面 (設定・ミニプレイヤー) へのすりガラス、Windows の Acrylic / Mica。
- 元ごとに別のマスクの濃さ・ぼかしを持つこと。

## Further Notes

- 2026-11-02 に開発版で確かめた事実 (CDP):
  - YTM の `<video>` は 1 つで、`blob:` (MSE)、640x360。`#movie_player` < `#song-video` < `#player` < `#player-page` の中にあり、`#player-page` には `transform` がかかっている。
  - `captureStream()` と canvas への `drawImage` はどちらもでき、画素も読める。
  - 再生中は `requestVideoFrameCallback` が 1 秒に 24 回届く。プレイヤーの画面を閉じても、「曲」モードでも届く (「曲」モードはジャケットの静止画)。
- 状態の図では、元の違いを「表示できる映像がある / ない」に畳んでいる。「元を切り替えた」「映像が来た」「ファイルが戻った」は、どれも「表示できる映像ができる」というきっかけにまとめた。
