# 再生中の動画は、YTM 画面の中に置いた canvas に描き写す

背景動画の元が「再生中の動画」のときは、YouTube Music のページの一番奥に canvas を置く。プレイヤーの `<video>` のフレームが届くたびに、それを canvas に描き写す。マスクとぼかしも同じページの中でかける。ADR 0001 は、背景動画のために YTM 画面の DOM に要素を足すことを避けたが、これはその例外にあたる。

ADR 0001 が DOM への差し込みを避けた理由は、主に次の 2 つだった。今回はどちらも当てはまらない。

- ローカルの動画を YTM 画面の別のセッションに渡しにくい: 写すのは、YTM 自身が再生している `<video>` で、ページの外から何も渡さない。
- YTM の CSP で読み込みを止められる: 新しく読み込むものが無い。

## Considered Options

- **`<video>` の要素を CSS で画面全体に広げる**: プレイヤーの画面 (`#player-page`) に `transform` がかかっていて、`position: fixed` が画面全体にならないので、採らなかった (2026-11-02 に実ページで確かめた)。
- **`captureStream()` の映像を WebRTC で背景動画のビューに送る**: ADR 0001 の作りのままにできる。しかし、つなぐ仕組みが大きく、映像の符号化と復号が余分にかかり、わずかに遅れるので採らなかった。

## Consequences

- canvas は YTM のページの DOM の一部になる。YTM の DOM が大きく変わると、描き写しが壊れることがある。
- 描き写すのは、YTM が選んだ画質 (例えば 640x360) の映像を拡大したもの。
- ローカルの動画ファイルは、これまでどおり ADR 0001 の背景動画のビューで流す。
