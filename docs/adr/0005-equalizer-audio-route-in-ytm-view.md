# イコライザの音の経路は YTM 画面の中に作り、使うまではつながない

イコライザとスペクトルのために、YTM 画面の中で、プレイヤーの `<video>` を Web Audio に通す (`createMediaElementSource`)。つなぐのは、利用者がイコライザを初めてオンにするか、スペクトルを初めて出すときだけにする。一度つないだら、YTM 画面が読み込み直されるまでつないだままにし、オフのときはすべての値を 0dB にした素通しにする。

`createMediaElementSource` は、1 つの要素に 1 回しか呼べず、つないだあとで元の出力に戻す手段が無い。そのため、起動したときに無条件でつなぐと、イコライザを使わない利用者の音も、すべてアプリの経路を通ることになる。経路のどこかに不具合があれば、使ってもいない機能のせいで音がおかしくなる。使うまでつながなければ、その心配は使った人にだけ残る。

音を取り出す場所を YTM 画面の外に置く案も考えた。しかし、YouTube Music の音は YTM 画面の中の `<video>` からしか取れない。ADR 0002 (再生中の動画の canvas) と同じく、YTM 画面の中に足すのは、音の経路と、パネル・背景のスペクトルの描画だけにする。設定とプリセットの持ち主は main にし、AI での調整の API Key と問い合わせも main に置く (ADR 0004 と同じ)。

## Considered Options

- **起動したときに必ずつなぐ**: オン・オフの切り替えがいつも同じ道を通り、初めてつないだときの音の途切れも起動時に済む。しかし、イコライザを使わない利用者の音まで経路に通すことになるので採らなかった。
- **オフのときに経路を外す**: `createMediaElementSource` でつないだ要素は、元の出力に戻せない。外すと音が出なくなるので、採れない。
- **YTM 画面の外で音を取り込んで加工する (画面の取り込み・ループバック)**: 曲の聞き取り (ADR 0003) と同じ取り込み方だが、加工した音を YTM 画面の代わりに鳴らす手段が無く、元の音と二重に鳴る。採らなかった。
- **音声のライブラリ (Tone.js など) を使う**: YTM 画面のスクリプトに import したものは、すべて Google のページのメインワールドに入る。Electron は Chromium だけなので、ブラウザの違いをならすライブラリも要らない。Web Audio の標準の部品 (BiquadFilterNode・AnalyserNode) だけで作る。

## Consequences

- 利用者が初めてイコライザをオンにした (またはスペクトルを出した) 瞬間に、音が一瞬途切れることがある。
- 一度つないだあとは、YTM 画面が読み込み直されるまで、イコライザをオフにしても音は経路を通る。オフの素通しで元の音と同じになることを、開発版で確かめる。
- YouTube Music がプレイヤーの `<video>` を別の要素に差し替えたら、新しい要素もつなぐ。古い要素の経路は捨てる。
- `<video>` の音量 (YouTube Music の音量・音量の比率の設定) は経路の手前で効くので、今の音量の仕組みはそのまま使える。
