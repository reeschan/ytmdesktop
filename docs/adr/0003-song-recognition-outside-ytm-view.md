# 曲の聞き取りの録音はアプリ画面で、Shazam への問い合わせはメインプロセスで行う

曲の聞き取りのアイコンは YTM 画面の検索欄の横に置く。それでも、音の元を録るのは YTM 画面ではなく、YTM 画面の下に常にあるアプリ画面 (`ytmd-app://` のローディング画面) にする。Shazam の API Key を持って問い合わせるのはメインプロセスにする。YTM 画面がやりとりするのは「聞き取りを始めて / 取り消して」という合図と、結果 (検索の文字列・状態・知らせの文) だけで、マイクの権限、PC の音の取り込み、API Key は YTM 画面に渡さない。

YTM 画面は Google のページで、アプリはその上に見た目と操作を足しているだけである。ここにマイクや画面の取り込みの権限を許すと、YouTube Music のページのスクリプトもそれを使えるようになる。API Key は使った分だけ課金されるので、ページの中に置かない。

音の元が「PC の音」のときは、このアプリ自身の再生も録れてしまう。YTM が再生中なら録音の間だけ一時停止し、録り終えたら再生に戻す。

## Considered Options

- **YTM 画面で録る**: アイコンと同じ場所なので作りは小さい。しかし、music.youtube.com にマイクと画面の取り込みの権限を許すことになるので採らなかった。
- **録音だけの見えないウィンドウを作る**: 役割は分かれるが、プロセスが 1 つ増える。常にあるアプリ画面で足りるので採らなかった。
- **アプリ自身の音を除いて録る (Chromium の `restrictOwnAudio`)**: 再生を止めずに済む。しかし、Electron 45 の Windows のループバックで効くかを確かめられなかったので採らなかった。効くと分かれば、一時停止をやめてこちらに替えられる。

## Consequences

- 録音はアプリ画面 (ローディング画面) の中で動く。この画面を作り替えるときは、録音の受け持ちを残す必要がある。
- 既定のセッションの権限の扱いに、`ytmd-app://` のアプリ画面だけに音声と画面の取り込みを許す決まりが加わる。
- 音の元が PC の音で再生中のときは、聞き取りのたびに曲が数秒止まる。
