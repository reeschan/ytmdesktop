- `isAuthValidMiddlewareAsync` は Fastify の async フックの作法から外れている (`Authorization` ヘッダーが無いとき 401 を送って `return reply` しない。トークンが不正なときは 401 を送ったうえで `Error("Unauthorized")` を投げる)。ただし 2026-11-03 に Fastify 5.12.7 と @fastify/rate-limit 11.2.1 で同じ設定を `inject` して確かめると、401 は 1 回だけ返り、ハンドラは走らず、二重送信の警告も出なかった。Fastify を上げるときは確かめ直す。
- `/command` は `RemoteControl` に送った時点で 204 を返す。YTM 画面がまだ読み込み中でポートが無いと、コマンドは黙って捨てられるが、クライアントには成功に見える。
- トークンの照合は、毎回 `safeStorage` で一覧全体を復号し、線形に比べる。リクエストごとに復号が走る。
- 0.0.0.0 で待ち受け、CORS の `*` が既定で有効。守りはトークン・レート制限・利用者による認可の画面での許可に頼る。
